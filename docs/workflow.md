# 🔁 Contribution Workflow Rules

This repository uses a structured contribution workflow to maintain quality, traceability, and clarity.

## 📌 Workflow Summary

| Rule                | Description                                              |
| ------------------- | -------------------------------------------------------- |
| 🔧 Task → Issue    | All work begins as a GitHub Issue                        |
| 🌿 Branch per Issue | Branch name must be `issue-<id>-<desc>`                |
| 📤 Commits          | Follow the commit convention in `commit_convention.md` |
| 📂 Pull Requests    | Must link to the issue and be reviewed                   |
| ✅ Merge Rules      | 2 non-authors must approve before merge                  |
| 🧹 After Merge      | Use "Squash and Merge", delete the branch                |

By following this structure, we ensure a maintainable, scalable codebase.
